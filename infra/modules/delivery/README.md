# Delivery IAM module

An immutable-tag ECR repository and two GitHub OIDC roles bind exactly the configured private repository's `main` branch and STS audience. Build pushes only this repository's images; ECR authorization tokens require resource `*`. Deploy only describes this EKS cluster and authenticates as `mybank:deployers`, whose Kubernetes Role permits the app rollout. Neither role is an AWS administrator. Branch/workflow/repository writers can assume both roles through trusted main workflows and must be treated as trusted releasers.

`github_oidc_subject_prefix` is required and must match the configured owner/repository exactly, optionally including numeric immutable owner/repository IDs. The sandbox uses the repository's verified API prefix `repo:aleduenas@54992507/mybank-eks-sandbox@1416500552`; the trust adds `:ref:refs/heads/main`. It rejects wildcards, other repositories and additional claim suffixes. Legacy name-only prefixes are supported for reuse only when the target repository actually emits that format. Verify the live subject and `github_oidc_subjects` output before AWS apply and after rename, transfer or OIDC-settings changes. See [GitHub immutable subject claims](https://docs.github.com/en/actions/reference/security/oidc#immutable-subject-claims).

`github_oidc_include_run_context` (default `false`) switches both roles to the custom repository subject template `repo`, `context`, `event_name`, `run_id`, `run_attempt` used by the [detection exercise](../../../docs/detection/README.md). The trust then becomes a `StringLike` match on `<prefix>:ref:refs/heads/main:event_name:{push|workflow_dispatch}:run_id:*:run_attempt:*`: still main-only, never `pull_request`, and wildcarded only in GitHub-signed run identifiers. Enable it together with the repository's OIDC subject template and the `MYBANK_OIDC_RUN_CONTEXT=true` repository variable read by the release claim check; changing one without the others breaks releases. `github_oidc_subjects` lists every accepted subject/pattern; `github_oidc_subject` returns only the first and is a pattern in run-context mode.

An account can have only one GitHub issuer provider. Set `existing_github_oidc_provider_arn` to reuse one; otherwise this module creates it. AWS validates GitHub through its trusted CA list, so no obsolete hard-coded thumbprint is embedded. The module does not create/register a runner or store its registration token. ECR cleanup preserves tagged releases; delete images deliberately before destroying a nonempty repository.
